# Kashout

![Kashout](docs/brand/logo.png)

**An open-source SwiftUI rewards-app prototype.**

[MIT license](LICENSE) · [Contributing](CONTRIBUTING.md)

Kashout explores daily rewards, animated reward-box reveals and a points-based
redemption interface. The source includes onboarding, account screens,
Firebase integration, rewarded-ad integration and StoreKit subscription code.

## Current status

Prototype, not a live rewards service. The repository now includes a
generated Xcode project with pinned dependencies, a demo mode that runs
without any Firebase configuration, and a small unit-test suite. The app
builds from a fresh clone, the tests pass, and the demo flow (onboarding,
home, reward reveal, simulated ad, subscriptions) runs in the iOS Simulator.

Firebase mode has not been exercised end to end against a real Firebase
project. There are no Firestore security rules or server-side checks, so
points are written by the client and nothing enforces them. Production ad
identifiers are placeholders, gift cards are never issued, and no build has
been published.

## Run it

Requirements: Xcode 27 or newer and an iOS 17+ iPhone simulator.

1. Clone the repository and open `Kashout.xcodeproj`.
2. Pick an iPhone simulator and run the `Kashout` scheme. Xcode fetches the
   pinned Swift packages on the first build.

From the command line, use any iPhone from `xcrun simctl list devices available`.
Add its `OS=` version when it is older than the newest SDK:

```sh
xcodebuild -scheme Kashout -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.5' build
xcodebuild -scheme Kashout -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.5' test
```

The project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `project.yml`. After changing targets, files or settings, run
`xcodegen generate` and commit both `project.yml` and `Kashout.xcodeproj`.

Dependencies are pinned in `project.yml` and in the committed
`Package.resolved`: firebase-ios-sdk 13.1.1 (Core, Auth, Firestore) and
swift-package-manager-google-mobile-ads 13.11.0.

## Demo mode

Without `Kashout/GoogleService-Info.plist` the app starts in demo mode and
shows an orange "Demo mode" banner. Everything stays in memory and resets
when the app is relaunched.

- **Account**: "Continue with Demo Account" signs in a mock user
  (`demo@kashout.test`, California, 10,000 starting points). Sign-up and
  sign-in also work against local data. Password reset is disabled.
- **Reward boxes**: the real odds and cooldown logic run against the mock
  user.
- **Ads**: "Watch Ad" shows a simulated full-screen ad. No ad network is
  contacted.
- **Subscriptions**: Pro plans use the prices from `Constants.swift`.
  "Subscribing" unlocks Pro locally. Nothing is charged.
- **Redemptions**: recorded on the device only. No gift card is issued.

Pass the launch argument `-KashoutDemoMode` to force demo mode even when a
Firebase config is present.

## Firebase mode

Copy your own Firebase project's `GoogleService-Info.plist` to
`Kashout/GoogleService-Info.plist`. The file is gitignored and is copied into
the app by a build phase when present.
`Kashout/GoogleService-Info.plist.example` shows the expected keys with
placeholder values. Enable Email/Password sign-in and Firestore in your
project, and add security rules before trusting any stored points.

Debug builds use Google's published test AdMob app ID and rewarded ad unit.
`Kashout.storekit` provides local StoreKit test products when the scheme is
run from Xcode. Never commit service credentials.

## Explore the source

- `Kashout/Views/`: onboarding, home, rewards, subscriptions and reveal screens.
- `Kashout/ViewModels/`: authentication and reward-flow state.
- `Kashout/Services/`: Firebase and demo backends, Google Mobile Ads and
  StoreKit adapters.
- `Kashout/Models/`: user and reward-box data structures.
- `Kashout/Config/`: prototype settings, placeholders and demo-mode detection.
- `KashoutTests/`: unit tests for odds, cooldowns, tiers and demo mode.
